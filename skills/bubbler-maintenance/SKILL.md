# 이력서 거품기 유지보수 지침

## 정체성

이 스킬은 콘텐츠를 변환하는 스킬이 아니라, **다른 두 스킬을 관리하는 메타 스킬**입니다. `이력서 거품기/techniques/` 디렉토리에 새 기법이 추가되거나 기존 기법이 수정될 때, 그 변경을 `resume-bubbler`와 `resume-debubbler` SKILL.md에 일관되게 반영합니다.

## 관리 대상 파일

| 경로 | 역할 |
|---|---|
| `techniques/{NN-기법명}/example.md` | 단일 진실 공급원 (SSOT). 모든 변환 패턴의 원본 |
| `skills/resume-bubbler/SKILL.md` | 정방향(평문→자소서) 변환 스킬 |
| `skills/resume-debubbler/SKILL.md` | 역방향(자소서→평문) 변환 스킬 |
| `README.md` | 기법 인덱스 |

원본은 항상 `techniques/`입니다. 두 스킬 파일은 techniques의 파생물이므로, 충돌 시 techniques를 우선합니다.

## 핵심 철학: 패턴은 닫힌 카탈로그가 아니다

두 스킬 SKILL.md에 적힌 변환 패턴들은 **에이전트가 참고하여 확장하는 출발점**입니다. 다음 원칙을 유지보수 작업 내내 지킵니다.

- 패턴은 "이런 사례가 있다"는 예시이지, "이 다섯 개만 적용하라"는 닫힌 규칙이 아닙니다.
- 따라서 SKILL.md에서 패턴 섹션을 키울 때도 "이게 전부"라는 느낌으로 쓰지 않습니다. "공통 메커니즘 + 대표 사례들"이라는 구조를 유지합니다.
- 새 기법을 추가할 때는 그 기법이 정말 별도의 패턴인지, 아니면 기존 공통 메커니즘으로 이미 커버되는 변형인지 먼저 판단합니다.

## 기법 추가 워크플로우

새 기법이 techniques/에 추가됐다는 신호를 받으면 다음 순서를 따릅니다.

### 1단계: 새 기법 example.md 읽고 파싱

새 기법 폴더의 `example.md`에서 다음 4개 정보를 추출합니다.

- **기법 번호와 이름**: 예) `06. 숫자 부풀리기`
- **부제**: 예) `정확한 수치를 모르면 어림짐작도 정량 지표가 된다`
- **Before/After 예시**: 변환 전후 텍스트
- **변환 패턴 분석**: 어떤 메커니즘이 작동하는지

`README.md`에도 새 기법이 인덱스에 추가됐는지 확인합니다. 안 됐으면 추가합니다.

### 2단계: 패턴 추가 여부 판단

새 기법이 기존 "공통 메커니즘"으로 이미 자연스럽게 처리되는지 먼저 점검합니다.

- 공통 메커니즘만으로 충분하다면, 별도 패턴을 추가하지 않고 공통 메커니즘의 설명이나 시범 예시에 한두 줄 보강만 합니다. 보강 시에도 "이 어휘만 쓰라"는 카탈로그·풀 형태가 아니라 "이런 종류의 조작"이라는 원리 설명으로 적습니다.
- 공통 메커니즘으로는 표현되기 어려운 고유한 프레임 전환이 있다면, 그때 새 패턴 섹션을 추가합니다.

이 판단을 통해 패턴 섹션이 비대해지는 것을 막습니다.

### 3단계: resume-bubbler/SKILL.md 업데이트

"참고 변환 패턴" 섹션에 새 패턴을 `### 패턴 N: 부제` 형식으로 추가합니다. 각 패턴은 다음 구조를 따릅니다.

```markdown
### 패턴 N: 부제

(1~2문장으로 메커니즘 설명)

- "Before 발췌" → "After 발췌"
- "Before 발췌" → "After 발췌"

격상 어휘: A→B, C→D, ...
```

기존 패턴의 표현·예시가 새 사례와 겹치거나 모순되면 함께 다듬습니다.

"공통 변환 메커니즘"에 새로운 일반 원리가 보이면 추가합니다. 다만 공통 메커니즘은 추상적 원칙들이므로 새 메커니즘이 추가되는 일은 흔치 않습니다.

### 4단계: resume-debubbler/SKILL.md 업데이트

"참고 역변환 패턴" 섹션에 동일 번호 패턴을 **역방향**으로 추가합니다. 거품기와 디버블러의 패턴 번호는 1:1로 짝지어 두는 것이 유지보수에 편합니다.

역방향 패턴 작성 시 점검 사항:
- 거품기에서 "A→B"였다면 디버블러에서는 "B→A"가 됩니다.
- 자소서 표현 B는 한 가지 형태로만 나타나지 않으므로, 가능한 변형들을 함께 다룹니다.
- "절대 금지" 섹션의 원칙(악의적 폄하 금지, 확신 과잉 금지)이 새 패턴에도 적용되는지 확인합니다.

### 5단계: 일관성 점검

두 SKILL.md를 나란히 놓고 다음을 확인합니다.

- 패턴 번호와 이름이 1:1로 짝지어지는가?
- Before/After 예시가 서로 거꾸로 일관되는가?
- 새 패턴이 기존 "절대 금지" 원칙을 위반하지 않는가?
- frontmatter의 `description`이 여전히 정확한가? (새 기법이 description의 트리거 표현 범위를 벗어나면 description도 업데이트)
- 두 파일 모두 "패턴은 출발점, 공통 메커니즘으로 확장 가능"이라는 톤을 유지하고 있는가?
- 두 파일의 "출력 포맷" 섹션이 `{"text": string, "copy": {"title": string, "desc": string}}` JSON 스키마를 강제하고 있는가? 새 패턴의 예시도 이 JSON 포맷으로 작성되었는가?
- 두 파일에 **Style transfer 원칙**(표면 사실 → 잠재 가치 추출 → 자소서 어휘) 또는 그 역방향이 살아 있는가? 새 패턴 예시가 단순 영문화/격식화에 그치지 않는가?
- 두 파일의 **copy 작성 절대 원칙**(패턴 헤드라인 그대로 복사 금지, 매 변환마다 입력 고유 카피)이 살아 있는가? 새 예시의 `copy.title`이 패턴명 그대로가 아닌가?

### 6단계: 변환 테스트

새 기법의 Before 텍스트를 거품기 패턴대로 적용하여 After가 나오는지, 거꾸로도 일치하는지 머릿속으로 한 번 굴려봅니다. 안 맞으면 패턴 표현을 다듬습니다.

## 기법 수정 워크플로우

기존 techniques/{NN-기법명}/example.md가 수정됐을 때:

1. 해당 기법 번호를 두 SKILL.md에서 찾습니다(`### 패턴 N`).
2. example.md의 변경분이 무엇인지 확인합니다(예시 추가? 어휘 변경? 메커니즘 재정의?).
3. 두 SKILL.md의 같은 번호 패턴을 동일한 방향으로 수정합니다.
4. README.md의 인덱스 한 줄 요약도 변경됐는지 확인합니다.

## 기법 삭제 워크플로우

techniques/에서 기법이 삭제됐을 때:

1. 두 SKILL.md에서 해당 번호 패턴을 제거합니다.
2. 뒷 번호 패턴들의 번호를 당기지 **않습니다**(번호는 안정적인 식별자). 빈 번호로 남겨두거나, 명시적으로 "패턴 N은 폐기됨" 주석을 답니다.
3. README.md 인덱스에서 제거합니다.

## 자기 점검 (정기 동기화)

사용자가 "동기화", "정합성 체크", "스킬 다시 학습" 같은 요청을 했을 때 다음을 수행합니다.

1. `techniques/` 폴더의 모든 example.md 목록을 만듭니다.
2. 두 SKILL.md의 "참고 (역)변환 패턴" 섹션 목록과 대조합니다.
3. 불일치(techniques엔 있는데 SKILL.md엔 없음, 혹은 반대)를 사용자에게 보고합니다.
4. 사용자 승인을 받고 위 워크플로우를 적용합니다.

## 작성 원칙

두 SKILL.md를 수정·확장할 때 지켜야 할 문체 원칙입니다.

- **참고용 톤 유지**: 패턴 섹션은 "이렇게 적용한다"가 아니라 "이런 사례가 있다"는 톤으로 씁니다. 닫힌 명령으로 읽히지 않도록 합니다.
- **공통 메커니즘 우선**: 개별 패턴보다 공통 메커니즘이 더 강력합니다. 패턴 섹션을 늘리기 전에 공통 메커니즘으로 표현 가능한지를 먼저 봅니다.
- **명령형이 아닌 서술형**: "~한다", "~합니다"로 메커니즘을 기술합니다. "반드시 ~해라" 같은 직접 명령은 피합니다(진짜 금지 사항만 "절대 금지" 섹션에 모읍니다).
- **예시 우선**: 추상 설명 한 줄보다 Before/After 예시 한 줄이 훨씬 강력합니다.
- **자기 격상 금지**: SKILL.md 자체가 거품 낀 문체로 쓰이면 안 됩니다. 평이하고 명확한 한국어를 씁니다.
- **한 패턴 한 메커니즘**: 한 패턴 안에 여러 메커니즘이 섞이면 둘로 분할하거나 공통 메커니즘 쪽으로 옮깁니다.

## 절대 금지

문서 톤은 풀어두지만, 다음 세 가지는 유지보수의 안정성을 위해 단호하게 지킵니다.

- **techniques 무시 금지**: SKILL.md를 직접 수정하면서 techniques/는 안 건드리는 것은 금지입니다. 항상 techniques가 먼저, SKILL.md가 나중입니다.
- **두 스킬 비대칭 금지**: 거품기에만 패턴을 추가하고 디버블러는 두고 가는 것은 금지입니다. 두 파일은 항상 짝으로 움직입니다.
- **번호 재배치 금지**: 기법 번호는 안정적 식별자입니다. 중간 번호가 삭제돼도 뒷 번호를 당겨오지 않습니다.

## 출력 포맷

작업을 마치면 다음 형식으로 사용자에게 보고합니다.

```
[동기화 결과]
- techniques/: N개 기법 (변동: +1 / -0 / 수정 0)
- resume-bubbler/SKILL.md: 패턴 N 추가
- resume-debubbler/SKILL.md: 패턴 N(역) 추가
- README.md: 인덱스 1줄 추가

[점검]
- 패턴 번호 1:1 대응: OK
- Before/After 역일관성: OK
- description 트리거 범위 점검: (필요 시 수정 사항)
- "패턴은 출발점" 톤 유지: OK
```
